## 阻断问题

### B1：栏目描述被现有首页状态当作空结果

- **需求与位置：** TV-HOME、REQ-TV3；`docs/ARCHITECTURE.md:168`、`docs/TASKS.md:1811`；现有 `src/state.ts:747-753`、`src/views/HomeView.vue:43-49`。
- **事实与影响：** `catalog_only` 被规定返回 `items=[]`、`has_next=false`。当前 `loadHome` 将所有栏目 `items` 均为空的完整首页设置为 `home.phase=empty`；HomeView 因而展示空态，不渲染后续可进入视口的栏目。描述中的“未请求”和实际请求成功后的“无内容”在 DTO 值上相同，必须由请求上下文或状态显式区分。
- **最小修订：** 在 T0.30 工作义务和 A1 中明确：栏目描述属于待加载状态；在有栏目描述时不得判为整页空结果，进入视口后请求第一页；仅首次实际内容请求完成且确为空时显示相应空态。验收应在真实 Host/窗口检查描述阶段零内容请求、可见栏首次请求、实际空栏目、失败/重试及来源切换。保持既定返回字段和原 16 项 cases。

### B2：同一栏目引用的多个筛选内容排缺少独立状态与竞态验收

- **需求与位置：** TV-HOME、TV-BROWSE、REQ-TV3；`docs/TASKS.md:1813-1816`；现有 `src/state.ts:724-757` 和 `mergeHome`。
- **事实与影响：** 首页须从同一 `tmdb.top` 引用生成动作、喜剧、科幻、剧情等多个排，从同一 `tmdb.year` 引用生成今年和去年排。现有请求作用域、局部状态及筛选缓存只以 `section_ref` 为键，响应按单个栏目 index 替换；不同筛选的同引用请求会互相取消、覆盖或共享分页。新 `catalog_only` 方案只返回原引用，当前文档未给页面排的独立身份及并发合并判据。
- **最小修订：** 明确页面排按来源及修订、语言世代、栏目引用和规范化筛选条件区分，独立保存加载、错误、结果和分页；旧响应不得覆盖新状态。A1 用真实 Host/受控 fixture 让同一引用的不同筛选并发及乱序返回，验证多个排同时显示各自内容、分页和重试不串用，并覆盖来源或语言切换。`src/state.ts` 已在 T0.30 范围内。

### B3：恢复定位修复缺少绑定到准确验收的回归要求

- **需求与位置：** TV-PLAYER、REQ-TV6；`docs/TASKS.md:1992-2033`、ADR-059；现有 `tests/acceptance/tv6.py:246-268` 和 `tests/playback.test.ts:56`。
- **事实与影响：** 新工作义务要求验证零位置暂停、非零恢复、时长夹取和会话身份；当前 A1 描述及冻结 cases 未明确覆盖该新增回归。现有 WIP 的 `tv6.py` A1 运行独立反例和真实窗口循环，未调用已复现失败的 `tests/playback.test.ts` 回归。完整 verify 的 `npm test` 会执行该文件，但单卡 A1 没有对应的明确失败门，随机窗口时序也可能不触发原竞争。
- **最小修订：** 保留全部原有 cases，给 A1 增加对应恢复定位的明确验收 case：执行零位置暂停竞争回归、非零及超时长夹取、旧会话事件隔离，并在真实窗口验证当前播放可暂停且不产生错误。验收脚本须以实际运行的非零测试数和结果支持该 case。
