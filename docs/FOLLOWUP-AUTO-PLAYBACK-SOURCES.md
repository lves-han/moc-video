## 0. 评审结论

### 0.1 第 2 版（多源查找）

1. **自动跨源确认与冻结契约 C5 冲突。** C5 规定仅「同一已验证外部 ID、类型且唯一季集」可自动确认。MacCMS 搜索候选的 `external_identity` 始终为空，所以按现行规则跨到 MacCMS 几乎全部是 `needs_confirmation`。已由 D1 与 C5 补充（ADR-075）解决。
2. **原生匹配与解析状态是单通道设计。** `MatchStore.begin` 在 `playback_source` 变化时清空记录，`match_playback` 与 `resolve_episode` 各自只保留最新一次调用，多源并行调用会互相取消。需要按轮次隔离的新命令。
3. **全局播放源还承担浏览职责**（侧栏综艺/短剧/体育、MacCMS 目录页与详情、搜索跳转、续播）。第 3 版的解耦使这些职责整体改变，见 0.2。
4. **与 T0.37 线路记忆（ADR-061）语义冲突。** 已由 D2 解决。
5. **测速须走现有网络约束并绕过媒体缓存。**
6. **缺协议、预算、权限和续播的落点。**

### 0.2 第 3 版（解耦与搜索质量）

7. **MacCMS 现在同时充当元数据源。** 用户可直接浏览 MacCMS 目录、打开 MacCMS 详情（命名空间 `maccms`），播放走 `match_maccms` 同源直通；搜索页也直接搜 MacCMS。涉及 `host.rs` 的 `match_maccms`、`state.ts` 的 `sameMacCmsSource`/`assertContext` 直通分支、`App.vue` 侧栏分类与 MacCMS 详情样式、`MacCmsCatalog.vue`、`SearchView.vue`、`WatchlistRow.vue`、`MediaRow.vue`、观看记录 `maccms` 命名空间。解耦后这些全部改为只用 TMDB/Stremio 元数据。
8. **跨源搜索只用英文片名。** `match_playback` 以 `"en"` 读取元数据（`stremio.rs` 注释「Matching itself always loads the English base」），别名只取「已经取过的本地化名称」。MacCMS 站点几乎都是中文片名，英文查询在优质、淘片返回 0 条，在其他站返回大量无关结果。
9. **各 MacCMS 站点的 `wd` 语义不同，原代码按「子串匹配」假设处理。** 2026-11-11 用「奥德赛 / The Odyssey」实测 8 个默认源：

   | 源 | 「奥德赛」 | 「The Odyssey」 |
   |---|---|---|
   | 优质 | 4 条，全部同名 | 0 条 |
   | 红牛 / 光速 / 极速 / 豪华 | 6 条，全部同名 | 72–74 条，首页 20 条无同名 |
   | 淘片 | 15 条，全部同名 | 0 条 |
   | 量子 | 466 条，首页 20 条仅 4 条同名 | 2000 条，首页仅 1 条同名 |
   | 无尽 | 超时 | HTTP 错误 |

   原代码把每次查询的前 10 条直接当候选，所以在量子上弹出的确认页几乎全是无关影片。

## 1. 目标与术语

- **元数据源**：TMDB（官方 API 或 Stremio 方式）与 Stremio 扩展。影片的浏览、搜索、详情、季集列表、观看记录身份全部来自元数据源。
- **播放源**：用户添加并启用的 MacCMS 格式来源，只提供线路与媒体地址。运行状态为 ready 且具备 `resolve`、`search` 能力的来源参与查找。
- **线路**：某个播放源中，目标影片目标集所在的一个分组（group）。
- **查找轮次**：针对「一个元数据影片 + 一个目标集」的一次完整查找与测速，有唯一 ID；新轮次开始时旧轮次作废。
- **查询片名**：用于在播放源中搜索的片名，按第 5.1 节取得。
- **自动选择 / 手动选择**：同第 2 版，前者选本轮延迟最低的已确认线路，后者展示列表由用户选择。

适用于网络影片与剧集。本地视频和直播沿用各自流程。

## 3. 用户界面

### 3.1 设置页与全局入口

- 移除 `SourceSettings.vue` 和 `HomeView.vue` 的「播放源」选择。
- 保留播放源列表及添加、编辑、启用、禁用、删除、诊断。来源行显示就绪、同步中、同步失败、已禁用。
- 元数据来源选择保留，是首页、目录、搜索页的唯一数据来源。
- 搜索页只搜索元数据源，「搜索来源」下拉只列元数据源。
- 侧栏分类按 D7 处理；MacCMS 目录页（`MacCmsCatalog.vue`）和 MacCMS 详情样式移除。

### 3.2 影片详情和播放器

- 详情页「播放」启动自动轮次；「选择线路」启动同样的轮次并展示列表。
- 播放器「线路」入口显示当前来源和线路，打开同一列表，可手动切换。
- 进度提示：查找阶段「已查询 5 / 8 个来源，发现 12 条线路」；测速阶段「正在检测 12 条线路」。结果逐条出现，手动模式下可在轮次结束前选择已测速线路。
- 列表展示来源、线路名称、可取得的清晰度、格式（HLS/文件）和状态：测速中、延迟、超时、失败、当前设备不支持。成功测速的按延迟升序，其余按状态分组排在后面。
- 需要确认的来源单独显示「需确认」，点击后进入候选确认界面；候选只显示通过第 5.3 节过滤的条目，每项显示片名、年份、类型、集数，并标出与元数据不一致的字段。确认后该来源的线路进入测速并加入列表。

示例：

| 线路 | 状态 |
|---|---|
| 来源 A · 线路 1 | 420 ms · 自动选中 |
| 来源 B · 线路 2 | 680 ms |
| 来源 C · 线路 1 | 超时 |
| 来源 D | 需确认（2 个同名候选） |
| 来源 E | 未找到 |

## 4. 播放流程

1. 用户在元数据详情中选择影片和集，点击「播放」或「选择线路」。前端生成轮次 ID，取消旧轮次。
2. 按第 5.1 节取得查询片名。
3. 对每个参与来源（有限并发）发起一次「来源查找」：搜索 → 第一级过滤 → 第二级筛选与确认 → 对已确认线路解析并测速。每个来源的结果独立返回。
4. 来源不可用、不支持搜索、失败、超时、过滤后无候选或缺少目标集时，记录该来源状态并继续其他来源。
5. 自动模式：所有来源完成或超时后，从成功测速且设备支持的线路中选延迟最低者，经现有 `resolve_episode` → `open_playback` 播放。没有可自动播放的线路但有「需确认」来源时，展示列表等待用户。
6. 播放器显示实际来源与线路。手动换线保留当前进度。
7. 切集时为新集启动新轮次；已确认的对应关系按 D2 复用，每集仍核对目标季集。
8. 播放失败按 D4 处理。
9. 从观看记录续播：以记录中的元数据影片和集启动自动轮次，记录里的 `source_id` 仅用于在列表中标注「上次播放」。

## 5. 搜索与匹配

### 5.1 查询片名（D9）

按顺序取最多两个不同的查询片名（与 C5「最多 2 次查询」一致）：

1. **应用语言片名**：按 `settings::metadata_language`（界面语言；TMDB 语言设为「跟随」时与界面一致）从元数据源读取的本地化片名，与详情页使用同一语言。详情页已按该语言加载时直接复用，无需再次请求；本地化请求失败或返回的身份与原影片不一致时（沿用 `stremio.rs` 的 `localized_identity_mismatch` 等校验）跳过此项。
2. **原始片名**：TMDB 的 `original_title`/`original_name`；取不到时用英文片名。

两项规范化后相同的只查一次。界面语言为英文时，第 1 项就是英文片名，第 2 项为原始片名。

### 5.2 查询

- 每个查询片名请求一次播放源 `ac=detail&wd=<片名>&pg=1`，读取整页结果（已修改 `match_search`，不再在过滤前截取前 10 条）。
- 不对查询片名做 T0.45 近似搜索式的放宽（去续集号、截前缀），以免扩大误匹配；该放宽只用于元数据源的搜索页。

### 5.3 第一级：片名过滤（D10，已先行修复）

- 规则：规范化后（全角转半角、去标点、小写），候选标题包含查询片名，或查询片名包含候选标题且候选标题至少 2 个字。实现为 `fuzzy::related`。
- 过滤后每个查询最多保留 10 条，与 C5「每次 10 候选」一致；两个查询合并去重后最多 20 条。
- 过滤后为空的来源记为「未找到」。
- 已在 `host.rs` 的 `match_playback` 中生效，并补了单元测试（用量子的真实返回标题作正反例）；该改动尚未提交。

### 5.4 第二级：程序筛选（D10）

对第一级留下的候选逐项判定，结果分为「排除」「可确认」「自动确认」：

1. **排除衍生内容**：`type_name` 含「解说」「预告」「花絮」等的条目已被 `maccms.rs` 的 `normalized_category` 在 `cards_limit` 中滤掉（量子的「奥德赛[电影解说]」属于「电影解说」分类，实测已不进候选）；这里只需补标题标记：标题含「解说」「預告/预告」「花絮」「片段」「彩蛋」「幕后/幕後」等的条目排除。标记表放在一个常量中，便于补充。
2. **类型**：搜索卡片的 `kind` 只有 movie、series、anime、other 四种（`category_kind`）。元数据为电影时排除 series，元数据为剧集时排除 movie；anime、other 不作排除依据。
3. **年份**：双方都有年份且不一致的排除；任一方缺年份的保留为「可确认」。
4. **季集**：搜索卡片不含分组与集（`card()` 只映射片名、年份、类型等），季集判定须对候选再取一次详情（`catalog.details`）。为控制请求数，只对第 1–3 步后剩下的候选取详情；目标集在分组中无法唯一对应的排除。对应规则只保留一套，在原生侧实现（见 5.5）。电影要求某个分组恰好一集。
5. **自动确认**：剩余候选中片名规范化后与某个查询片名完全一致、年份一致、季集唯一对应，且该来源只有这一个候选满足，按 D1 自动确认；有共同外部 ID 时按现行 C5 确认。
6. 其余进入「需确认」，界面只展示这些候选。

以「奥德赛」（2026 电影）为例：量子第一级留下「奥德赛 / 奥德赛[电影解说] / 艾洛：拉普兰的奥德赛 / 尤利西斯：黑暗的奥德赛」；第二级排除解说、排除年份 2018 的两部，剩「奥德赛（2026，动作片）」并自动确认。优质第一级留下 4 条，第二级排除 2016、2025 两部和记录片「奥德赛-真实的故事」后剩「奥德赛2026」。它与查询片名不完全一致，所以按 D1 进入确认；若希望这种「片名 + 年份」后缀也自动确认，可在 5.4 第 5 步把「片名去掉末尾年份后一致」视为一致（建议采纳，属于 D1 的规范化范围）。

### 5.5 集对应

- 前端 `episodeCoordinates`/`correspondingEpisode`（`src/line-preference.ts`）与原生 `matching::search` 的季集比较不一致。多源查找在原生侧完成，把前端规则移植到 Rust 作为唯一实现，前端不再重复判定。

## 6. 测速定义

线路延迟：从开始请求该线路媒体，到收到首批媒体数据的耗时。

- 普通文件：带 `Range: bytes=0-65535` 请求，读到首批数据即停止。
- HLS：取播放清单；若为主清单，按网关现有变体选择规则选一个变体并取其清单；再取首个媒体分片的首批数据。延迟计为整个链条耗时。
- 网络栈：使用 `maccms::Http` 及解析得到的请求头，沿用 ADR-049 的 DNS 与内网拦截、跳转上限和 HTTPS 降级规则。
- 绕过媒体磁盘缓存（ADR-054），测速请求不写入缓存。
- 解析结果 `playable == false` 或格式不被当前播放器支持的线路标为「不支持」，不测速。
- 测速不打开网关会话、不登记 Resolution、不写观看记录。用户选定后由 `resolve_episode` 重新解析。
- 每条线路每轮只测一次。

## 7. 并发、超时与取消

- 来源查找与线路测速分别限制并发，初始建议各 4，实测后确定。
- 来源查找上限初始 15 秒（沿用 `match_playback` 的 `child_ms`），单条测速 5 秒；写入 `x-request-budgets`，实测后确定。
- 切集、离开详情或播放页、重新发起、手动换线时取消旧轮次的全部未完成请求；原生侧提交前核对轮次 ID，过期结果丢弃并释放匹配记录。
- 一个轮次的匹配记录保留到下一轮开始；正在播放的匹配记录保留至播放结束。

## 8. 实现改动

### 8.1 原生（`src-tauri/src`）

- 新增命令 `find_source_lines`，输入 `{round_id, metadata_ref, video_id, playback_source}`，输出来源状态、需确认候选（含不一致字段）和线路 `{line_id, content_ref, group_id, episode_id, match_id, label, kind, quality, probe: {status, latency_ms}}`。每个来源一次调用，前端控制并发。
- 查询片名（5.1）：`match_playback` 与新命令按 `settings::metadata_language` 取本地化片名。先用 `stremio::Catalog::match_aliases` 的缓存（只缓存 zh-CN，用户打开过中文详情时即有）；缓存缺失时调用 `metadata_catalog.details(…, language, …)`，仅当返回的 `metadata_ref` 与输入一致才采用；本地化请求失败时跳过此项并继续用基础片名。`matching::search` 的查询顺序改为「本地化片名在前、基础片名在后」；取原始片名需要在 TMDB 详情映射中保留 `original_title`/`original_name`；当前 `tmdb_api.rs` 与 Stremio 映射都没有保留该字段，须补上（只用于匹配，不进界面 DTO）。
- 第一级过滤 `fuzzy::related`（已完成）；第二级筛选新增在 `matching.rs`，与 D1 自动确认在同一处实现。
- `MatchStore` 按轮次保存记录；新命令不递增 `matches.sequence` 与 `resolve_sequence`。
- 测速函数放在 `maccms.rs`，复用 `Http` 与 `hls.rs` 清单解析。
- 删除 MacCMS 作为元数据的路径（D8）：`match_maccms`、`namespace == "maccms"` 的元数据身份与详情映射中的 `metadata_ref`、MacCMS 首页/目录命令中仅服务浏览的部分；保留播放所需的搜索、详情（取分组）、解析。观看记录与收藏中 `maccms` 命名空间的数据不再读取。

## 9. 验收场景

1. 三个受控来源提供同一影片和集、延迟不同：所有来源都被查询，自动选中延迟最低的线路并实际播放。
2. 一个来源不可用、一个超时、一个缺目标集、一个不支持搜索：其余来源照常完成，列表显示对应状态，整轮在超时上限内结束。
3. 查询片名：界面为中文时先用中文片名、再用原始片名查询，界面为英文时先用英文片名；本地化片名身份不一致时跳过。会被拒绝：中文界面仍只用英文片名查询。
4. 第一级过滤：模拟全文检索的来源返回大量无关标题时，候选只含片名相关条目；子串匹配的来源结果不受影响；过滤后为空记为「未找到」。
5. 第二级筛选：解说/预告类条目、类型不符、年份不符、季集无法对应的候选被排除；剩余唯一且完全一致的自动确认；同名多候选、缺年份同名进入确认。用「奥德赛」的真实返回形态作夹具。
6. 详情页手动选线播放；播放器内换线后从原进度继续。
7. 切集、退出、连续点击播放：旧轮次请求被取消，迟到结果不覆盖新轮次，匹配记录与临时资源被回收。
8. 测速成功但播放失败：自动换下一条并提示；全部失败时展示原因、重试与手动选择。
9. 测速绕过媒体缓存；指向内网地址或超出跳转上限的线路测速失败。
10. 设置页无播放源选择，来源管理完整；禁用来源后新轮次不再查询它。
11. 解耦：首页、目录、搜索页、详情只出现 TMDB/Stremio 内容；MacCMS 目录入口与 MacCMS 详情不存在；侧栏分类按 D7；观看记录续播只走元数据影片。
12. 使用受控 HTTP、普通视频和 HLS 夹具验证排序、超时、错误和资源回收；真实播放器验证播放、换线和续播。
