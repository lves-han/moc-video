# T01 视频样机交接

本机 macOS 14+ arm64 必需；其余目标按 ADR-005/006 保留 NOT RUN。
本卡完成证据由准确 A1、完整 verify、原 done、受验提交及独立 CLEAR 共同建立。

## 最小实现

- 沿用现有 Vue/Vite/UiProvider 和样式；`#/prototype` 为独立视频样机，原 App 入口保持。
- Rust Tauri `2.12.5`、tauri-build `2.7.4` 来自 T00 固定上游源码；hls.js `1.7.3` 使用 T00 获取的 npm tarball URL 与 SHA512 integrity 写入原 npm 锁。
- 使用 Cargo 和 Tauri 全局 `core.invoke`，当前样机直接构建应用壳。后续发行安装器/签名公证由 T23/T24 承接。
- `src-tauri/icons/icon.png` 沿用 `public/mark.svg` 的圆角底色和四条圆头线条，栅格化为 256×256 RGBA；锁定版 tauri-codegen 在 Unix 平台默认读取该文件作为窗口图标。
- video 原生 MP4，HLS 优先原生、其次 hls.js；状态由媒体事件驱动。stop 暂停、销毁 HLS、移除 src/track、load 复位及解除监听。
- 生产 CSP 的脚本来源为打包资源；媒体、图片和连接限于本地应用、必要 IPC 与 `http://127.0.0.1:*`。ATS 只声明本地网络例外。
- Python loopback fixture 位于 `tests/fixtures/t01/`，随机端口、256 位 cap、固定应用 Origin、登记资源、64KiB 流式读取、Range/If-Range/HEAD/OPTIONS。生产打包排除服务器及自动验收桥。
- `t01-automation` Rust feature、Vite `t01` mode 和额外的单窗口权限共同启用验收。生成的 production/test `.app` 分开保存；二者均使用真实 Tauri WKWebView。

## 外层执行顺序

依 ADR-010，等待当前开发 CLI 和旧重命令退出，确认源码稳定，再以原 run.py 串行执行。
机器可读 argv 见 `packaging/t01-commands.json`。仅把外层 argv 首项 `{python}` 替换为当前项目解释器；run.py 的 `--` 后保留字面 `{python}`。

1. `prepare`：npm ci、首次生成 Cargo.lock 后 locked fetch、FFmpeg 生成自有 1920×1080/30fps H.264 + 48kHz stereo AAC 测试图/440Hz 音调和 HLS。Cargo.lock 属于此卡范围，外层保留真实解析结果并纳入 WIP/完成提交。已有媒体摘要逐字节校验，保留首代基准。
2. `build`：类型检查/Vite 构建、Cargo locked release，生成生产 `.app`；再以测试 feature/mode/config 构建测试 `.app`。共享原 `target/`，jobs=2。应用采用本机 ad hoc codesign；Apple 发行签名留后续卡。
3. 准确 A1：`--suite all`，JSON/JUnit 输出保持卡片原 argv。含 fixture/证据验证器回归、真实窗口安全负例、MP4 与 HLS 各 1800 秒、20 次完整原生窗口开关、控件/字幕/全屏、360/390/768/960/1200 和 125%/150%/200% 等效 page zoom。
4. A1 通过后直接 `scripts/verify.py all`，不套 run.py；进程局部环境 `ROLLDOWN_WORKER_THREADS=2`、`RAYON_NUM_THREADS=2`，沿用 T00。通过后按原流程勾卡、记录、done、受验提交、review-only。

完整 A1 原生播放约 65 分钟；构建放在独立准备命令内。原 A1 7200 秒、4096MiB RSS 采样、jobs2、测试线程1及会话预算保持。
macOS GUI 会话须可见并保持前台；系统阻止 autoplay/AudioContext 时保留明确失败和继续播放按钮，交原开发工作流复现。

## 证据与回收

- `evidence/t01/media/manifest.json`：首代生成命令、FFmpeg/ffprobe、编码/900 帧/时长和所有文件 SHA256。原图/音调由本项目生成，CC0-1.0；hls.js Apache-2.0、Tauri Apache-2.0 OR MIT，完整发行告知留 T23。
- `evidence/t01/build.json`：生产/测试应用文件 SHA256、受验源码/保护摘要、Cargo.lock 摘要及构建日志。Tauri build-time codegen 跟踪前端资源，重新嵌入发生变化的资源。
- `evidence/acceptance/T01-<运行>/`：脱敏原生日志、每 5 秒的真实帧/媒体时钟/WebAudio RMS/频谱峰、RAF、原生 renderer/GPU/network PID、PID 创建时间及 RSS；JSON 保留解码帧预览和循环记录。
- 测试 feature 通过 WebKit 的诊断 SPI 取得当前 WKWebView 的 renderer/GPU/network PID，补齐 launchd XPC 的进程归属。接口缺失、renderer 缺测、权限失败均使 A1 失败；生产产物检查排除 SPI 标识。依据为 WebKit `WKWebViewPrivate.h` 与 `WKWebsiteDataStorePrivate.h`，仅作本机技术门诊断。
- 原 run.py 保留宿主进程树 RSS 采样；A1 额外合并该树与当前 WebView XPC PID，去重核算 4096MiB。后端如实记录为 RSS sampled/build jobs；瞬时采样间隔保留。
- 音频证据为真实媒体 PCM 经 WebAudio 连到系统默认输出的 RMS/440Hz 峰值和运行状态；物理扬声器的听感尚待人工确认。帧证据为 presentation callback、播放质量计数及实际解码像素。记录原始样本，避免填造感知结果。
- 正常关闭后的存活进程、媒体请求、fixture 端口或输出线程使验收失败。失败/取消仍按 PID＋创建时间清理本次创建的对象，并记录 forced_cleanup；日志对 cap 脱敏。

## 延期目标

所有重命令仍需原 run.py；迁移前按 C1 重新核实真实项目根、解释器、共享锁与授权。

| 目标 | 当前记录 | 系统依赖及原生复现入口 |
| --- | --- | --- |
| macOS x86_64 | NOT RUN | Intel/Xcode/WebKit，Rust `x86_64-apple-darwin`；`cargo build --locked --release --manifest-path src-tauri/Cargo.toml --target x86_64-apple-darwin` |
| Windows x86_64 | NOT RUN | MSVC Build Tools、系统 WebView2；target `x86_64-pc-windows-msvc`，同上 Cargo argv 替换 target |
| Ubuntu X11 | NOT RUN | GTK3、WebKitGTK4.1、GStreamer good/bad/libav，target `x86_64-unknown-linux-gnu`；启动时 `GDK_BACKEND=x11` |
| Ubuntu Wayland | NOT RUN | 同上依赖；启动时 `GDK_BACKEND=wayland` |

报告始终列出四个延期目标、精确原生 build/launch argv 和环境。当前完整自动验收宿主适配为本机 macOS arm64；其他平台的完整媒体/长测适配随相应平台授权继续。

当前开发会话：真实构建、行为测试、A1 长测、音频听感及完整 verify 均 NOT RUN。静态检查记录与最终交接见 docs/PROGRESS.md。

## T0.2 第四会话修复交接

- 原生 `inner_size` 继续精确验证逻辑 1200×800；macOS 测试 feature 额外读取 WKWebView 的 `_topContentInset`，以 `(原生逻辑高度 - 实测 inset) / zoom` 核对 CSS 视口高度。保留实际物理尺寸、scale、inset 和视口，避免固定填入 32px。诊断缺失或尺寸差异无法由读数解释时明确失败。
- 此诊断复用既有测试专用 Objective-C 读取路径，生产制品排除门新增 `_topContentInset` 标识。生产窗口、依赖版本、媒体基准及长测时长保持。
- 布局同时记录原生表单控件与其 label 点击区域；44px 门检查按钮/label，原生 checkbox/select 的视觉尺寸保留。每个点击区域滚动到视口内并通过命中测试验证可达性，360/390/768/960/1200 及 zoom 共用此行为验证。
- 需求汇总行包含真实失败子用例的 ID、expected、actual 和 evidence；失败 JSON 与 JUnit 同时输出。回归覆盖真实尺寸差异的语义、错误尺寸/inset、失败报告、缺失需求覆盖、必需项跳过及延期平台跳过。
- 本开发会话只完成静态核对。外层在本 CLI 退出后代办 WIP 提交，依 `t01-commands.json` 顺序执行 `build` → `optional_negatives` → `acceptance` → `verify`；首代媒体和已锁定依赖沿用，所有新行为门仍为 NOT RUN。
