## 外层执行顺序

沿 ADR-010/045，先确认本开发 CLI 已退出、源码稳定、真实 PID/创建时间和原共享重锁空闲。保持原权限、4096MiB 进程树 RSS 采样、jobs2、测试线程1、原超时与失败历史。以下数组首个 `{python}` 由宿主替换为本项目实际虚拟环境解释器；run.py 后的占位符交原执行器解析。

1. 先执行相关反例和许可验证：

```json
["{python}", "-B", "scripts/run.py", "diag-t23-oracles", "--", "{python}", "-B", "-m", "unittest", "discover", "-s", "tests/acceptance", "-p", "test_t23.py", "-v"]
["{python}", "-B", "scripts/run.py", "diag-t23-license-verify", "--", "{python}", "-B", "packaging/release.py", "--verify-licenses"]
```

2. 构建正式制品。准确 ID/argv 由 A1 核对；不复用初步 0.1.1 包：

```json
["{python}", "-B", "scripts/run.py", "diag-t23-release-build", "--", "{python}", "-B", "packaging/release.py", "--build"]
```

该命令先复算许可，再运行 `npm run build`、`cargo tauri build --ci --bundles app --no-sign -- --locked --offline`，随后密封副本并归档。源码全程保持同一摘要。构建清单记录实际文件逻辑体积、文件 st_blocks×512 占用及下载大小；目录和文件系统元数据开销由 OS 决定。归档重现使用同一 argv 和载荷，ZIP 时间戳、DMG 文件系统 UUID 可能变化，逐份记录实际 SHA256。

3. 执行冻结 A1：

```json
["{python}", "-B", "scripts/run.py", "A1", "--", "{python}", "-B", "tests/acceptance/t23.py", "--suite", "all", "--report", "evidence/acceptance/T23-all.json", "--junit", "evidence/acceptance/T23-all.xml"]
```

每次 A1 将完整 JSON 留在本次唯一 T23 证据目录的 report.json，并把 SHA 打印至原资源日志；后续重跑保留旧报告。缺干净目标证据时，该运行仍检查独立产物并输出真实失败报告。先按原 note 记录失败及具体缺项，保留报告和收据；不得据此勾卡或 done。全部 A1 通过后才直接执行 `["{python}", "-B", "scripts/verify.py", "all"]`，随后按原规则 handoff、勾选、追加 PROGRESS、done、完成提交和新独立 `drive.py --review-only`。最终固定提交 CLEAR、干净树后交外层停止/删除同聊天 automation-2。本会话仅 T0.27，T0.28 留待后续指令。

## 签名与默认安全设置

Apple Developer ID、完整 ad-hoc 资源密封、Gatekeeper 评估和公证/装订分项记录。没有 Apple 凭据时产出本地 ad-hoc 包，Developer ID 与公证状态为 false，notarization submission 写 NOT RUN。密封验证失败、资源被改写、把 ad-hoc 声称为 Developer ID/公证通过都会使 A1 失败。

当前仍为 NOT RUN。用户已收到外层关于 UTM/另一台 Mac 的异步问题，当前会话不重复提问、不启动或改动既有 VM。已发现 UTM 的 macOS arm64 VM 配置为 4096MiB，清洁状态、桌面与使用授权待核实；原总采样预算仍为 4096MiB，VM 和宿主合计需满足原预算后才可启动。临时 HOME 和已有开发机应用只记录其真实测试范围。

目标为干净 macOS 14+ arm64，可用桌面和默认安全设置。观察者使用独立环境，记录清洁来源（全新安装、恢复干净快照或独立干净 Mac）、系统版本与实际安装路径。诊断/录制工具属于测量工具，不作为应用运行依赖。只用受控测试数据和自有或获准媒体，不录入账户、令牌或签名播放 URL。

按以下顺序进行；所有步骤保留准确 UTC、操作日志及屏幕证据。应用从 Finder 正常启动：

1. 安装前确认目标 Applications 中无本应用、应用数据目录无本应用数据；记录 `/usr/sbin/spctl --status` 与 `/usr/bin/csrutil status` 的原始输出和退出码，保留传输归档的 quarantine 状态。

3. 初始化并显示 ready 的正式主窗口，保存一项实际设置，复制关闭应用后生成的 `settings.json`。用正式来源/网关播放媒体；至少两次记录实际进度，间隔≥5秒且前进>2秒，见到活动画面并听到音频。保存包含正式应用画面和声音的实际录制（可用外部相机拍摄屏幕/扬声器）及观察日志。录制覆盖完整首播观察区间。
4. 退出应用，清理本流程创建的测试应用和测试数据以建立升级初态；保留清理与新 profile 的证据。把 `T22-upgrade-fixture-0.1.0-build1.zip` 的真实 build 1 app 安装到相同目的地（其归档内名称为 YingxiangVideo.app）。正常运行旧包，添加受控来源、更改非默认设置并产生非空历史，然后关闭。保存旧包文件树、设置全文和 SQLite 一致备份。

### 外部原始证据格式

将目标证据完整返回项目的 `evidence/releases/T23-clean-macos/`；入口为 `observations.json`。它记录人类实际操作和原始观测，没有预填 PASS 样例。顶层字段：

| 字段 | 内容 |
| --- | --- |
| manifest_sha256, source, protected | 本次不可变 manifest 的 SHA 与其中源码/保护摘要 |
| target, macos | macos-arm64、目标真实系统版本 |
| clean_system_method | fresh-macos-install / restored-clean-snapshot / separate-clean-mac |
| human_observer | 实际观察者标识 |
| security_settings_changed, quarantine_removed, security_exceptions | 实际布尔值与例外列表；本验收要求 false、false、[] |
| security_commands | 两条系统安全查询，逐条含 argv、exit、evidence（原输出文件的材料 ID） |
| artifacts | 材料 ID → {path, sha256}；path 为项目相对路径且须位于当前 clean-macos 目录 |
| recording | 首播录制的材料 ID |
| phases | 下列八个阶段，逐条含实际 utc 与非空 evidence 材料 ID 列表 |

阶段按表顺序发生，时间晚于本次构建；各原始文件均非空且 SHA 匹配。

| 阶段 | 实际字段和原材料 |
| --- | --- |
| baseline | app_exists=false、data_exists=false；干净安装前屏幕、目录清单/清洁来源 |
| installed | destination、file_tree（目标安装文件树 JSON 的材料 ID） |
| initialized | window_visible、ready、settings_file（目标设置原文材料 ID） |
| first_play | samples[{elapsed_seconds,position_seconds}]、moving_picture、audio_audible、errors；evidence 含 recording |
| upgrade_before | ready、file_tree、settings_file、history_db；对应实际 build 1 |
| upgrade_after | window_visible、ready、file_tree、settings_file、history_db；对应实际 build 2 |
| uninstalled | app_exists、data_exists、settings_file、history_db；数据原文与升级后保持一致 |
| data_deleted | app_exists、data_exists、explicit_test_data_deletion、remaining_owned_processes；对应显式测试数据清理 |

file_tree JSON 使用实际安装文件相对 app 路径作为键，值为 {sha256, bytes, mode}，mode 为 POSIX 权限十进制整数（如可执行文件 0755 对应 493）。与 release.tree 同一测量定义，可通过目标系统的文件 SHA/stat 输出形成；保留实际测量命令。evidence 列表须包含本阶段引用的 file_tree/settings_file/history_db 材料。

A1 重新读取安全日志、文件树 JSON、设置原文和真实 SQLite；报告内预填 settings/history/app_files/output 值均由原材料重读值覆盖。录制会由宿主 ffprobe 解码计数，要求至少5秒、有视频帧和音轨，再由 ffmpeg 解码 PCM 核对非零音频能量，测量日志省略相机位置及设备元数据。画面、UI 进度和声音的来源关联由实际观察者及原录制共同记录，属于人类执行的干净机器验收。缺材料、空材料、静音/缺音轨、同包伪升级、丢数据或安全例外都会失败。

macos-x86_64、windows-x86_64、linux-x11、linux-wayland 均为 NOT RUN（ADR-005/006，缺目标环境）；当前复现入口与迁移前提记录在 A1 的 deferred 项。
